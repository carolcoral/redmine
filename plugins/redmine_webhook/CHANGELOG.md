# 更新日志 (Changelog)

## [1.0.4] - 企业级部署优化

### 🚀 新增功能

#### 任务提醒功能
- 自动每日提醒项目成员记录工时或更新任务
- 支持自定义提醒时间（小时：分钟）
- 支持自定义提醒消息模板
- 智能过滤：仅提醒当天无任务的在岗成员
- 支持多项目并行提醒
- 钉钉集成：支持@提醒多个用户

#### 多容器部署支持
- 数据库分布式锁实现，防止多容器重复发送消息
- 自动回退机制：数据库锁不可用时自动切换到缓存锁
- 默认使用数据库锁，无需额外配置
- 锁TTL自动管理（26小时过期）

#### 在岗状态智能识别
- 工作状态为空的成员默认视为在岗
- 支持自定义"在岗"状态值
- 灵活的状态配置机制

#### 多用户@提醒支持
- 支持多个用户共享同一个手机号
- 有手机号用户：同时使用atMobiles和@phone文本提醒
- 无手机号用户：使用@昵称文本提醒
- 确保所有相关用户都能收到提醒

### 🔧 修复改进

#### 代码质量优化
- 移除所有调试日志输出，精简生产日志
- 优化日志级别，仅保留关键信息
- 清理所有测试和诊断文件
- 添加Zeitwerk自动加载器配置，防止文件加载冲突

#### 错误处理增强
- 数据库锁初始化失败自动回退到缓存锁
- 任务提醒启动失败不影响主服务运行
- 完善的异常捕获和日志记录

#### 数据库兼容性
- 虚拟属性模式：任务提醒字段动态getter/setter
- 平滑迁移支持：无需数据库迁移即可使用新功能
- 自动回退：字段不存在时使用默认值

#### 子项目同步扩展
- 任务提醒配置同步到子项目
- 完整的字段同步包括启用状态、时间、模板等

### 🐛 修复的Bug

1. 多容器部署导致消息重复发送
2. 任务提醒模板无法保存到数据库
3. 子项目同步未包含任务提醒配置
4. 空工作状态成员被错误排除
5. 多个用户共享手机号时只有一个收到@提醒
6. 服务启动时Zeitwerk自动加载诊断文件导致错误

### 📈 性能提升

- 数据库锁查询优化，减少锁竞争
- 日志输出优化，减少I/O开销
- 批量查询在岗用户，减少数据库访问次数

### 📝 升级说明

```bash
cd /path/to/redmine
git pull origin v1.0.4
bundle exec rake redmine:plugins:migrate RAILS_ENV=production
bundle exec rake tmp:cache:clear RAILS_ENV=production
# 重启Redmine服务
touch tmp/restart.txt
```

**配置任务提醒功能（可选）：**
```ruby
# 1. 运行数据库迁移（如果还未执行）
bundle exec rake redmine:plugins:migrate RAILS_ENV=production

# 2. 启用任务提醒（通过Web界面）
项目 → Webhook设置 → 任务提醒 → 启用

# 3. 配置提醒时间和模板
```

**多容器部署注意事项：**
- 确保所有容器共享同一个数据库
- 数据库锁表`webhook_locks`自动创建
- 无需额外配置，系统自动使用数据库锁

## [1.0.3] - 功能增强与优化

### 🚀 新增功能

#### 智能@提醒（DingTalk）
- 基于Redmine自定义字段实现真正的钉钉@提醒功能
- 通过用户手机号实现钉钉强提醒（弹窗+红色标记）
- 自动从`custom_fields`和`custom_values`表读取手机号
- **重要规则**：仅在模板中包含`${assigned_to}`变量时才会触发@功能
- 智能避免重复显示：有手机号时不显示`${assigned_to}`值
- 支持Markdown和纯文本两种消息格式
- 纯文本格式使用`atMobiles`参数实现强提醒
- Markdown格式将@信息嵌入消息内容

#### 子项目同步
- 一键将当前项目webhook配置同步到所有子项目
- 支持多级子项目递归同步（不限层级深度）
- 自动检测子项目是否启用webhook模块
- 智能冲突处理：已存在配置时更新，不存在时创建
- 使用数据库事务确保操作原子性
- 实时显示同步统计结果（创建/更新数量）

### 🔧 修复改进

#### UI/UX优化
- 修复Redmine 6.1+菜单高亮问题
- 使用`setTimeout`延时确保Redmine菜单初始化完成
- 同时监听`DOMContentLoaded`和Turbo/Turbolinks事件
- 分别处理`<a>`标签和父级`<li>`元素的`selected`类
- 优化配置页面视觉设计（渐变背景提示框）
- 改进子项目选择界面（网格布局、批量操作）
- 响应式设计优化，适配不同屏幕尺寸
- 将模板输入框改为文本域，支持多行内容
- 提供所有可用变量的详细说明表格
- 改进占位符文档折叠面板样式

#### 代码质量优化
- 使用IIFE避免JavaScript全局污染
- 添加`use strict`严格模式
- 优化DOM查询和操作性能
- 完善错误处理和日志记录

#### 状态配置持久化改进
- 使用状态名称（name）而非ID作为配置键
- 解决状态顺序变化导致的配置错乱问题
- 使用Rails serialize YAML序列化数组数据
- 完善Strong Parameters数组参数处理

#### 数据库查询优化
- 使用递归CTE查询获取所有子项目
- 兼容PostgreSQL、MySQL、SQLite
- 减少数据库查询次数，提升性能

### 📚 文档完善

- 优化README.md结构（精简50%内容）
- 创建CHANGELOG.md记录版本历史
- 添加详细的@功能配置指南
- 补充故障排查指南和完整示例

### 🐛 修复的Bug

1. 状态配置无法保存（强参数问题）
2. 模板映射使用错误的状态ID
3. 表单提交后状态配置丢失
4. 子项目同步创建重复记录
5. 菜单高亮不生效（Redmine 6.1+）
6. 文本域不支持多行输入
7. ${assigned_to}变量重复显示
8. customized_type查询错误（应为Principal）

### 📈 性能提升

- 子项目查询：从N+1查询优化为1次CTE递归查询
- 模板渲染：减少不必要的字符串操作
- 数据库写入：使用事务批量操作
