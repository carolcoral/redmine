## 安装部署

### 前置要求

- Redmine 6.1+
- Ruby 2.7+
- 数据库：PostgreSQL / MySQL / SQLite

### 安装步骤

1. **克隆插件到 Redmine 插件目录**

```bash
cd /path/to/redmine/plugins
git clone https://github.com/carolcoral/redmine_webhook.git redmine_webhook
```

2. **安装依赖**

```bash
cd /path/to/redmine
bundle install
```

3. **执行数据库迁移**

```bash
bundle exec rake redmine:plugins:migrate RAILS_ENV=production
```

4. **重启服务**

```bash
# Passenger 或 Puma
touch tmp/restart.txt

# 或重启整个服务
service redmine restart
```

5. **启用模块**

进入 **项目 → 设置 → 模块**，勾选 **Webhook** 模块。

## 钉钉机器人配置

### 创建自定义机器人

1. 在钉钉群中，点击右上角 **...** → **群设置**
2. 选择 **智能群助手** → **添加机器人**
3. 选择 **自定义** 机器人
4. 填写机器人名称（如"Redmine 通知"）
5. 选择安全设置（推荐启用**加签**）
6. 点击 **完成**，复制 Webhook URL

### Webhook URL 格式

```
https://oapi.dingtalk.com/robot/send?access_token=xxxxx
```

### 签名验证（推荐）

1. 在创建机器人时，选择 **加签** 安全设置
2. 复制生成的 **密钥（Secret）**
3. 在插件配置中填写该密钥

**注意**：如果启用加签，必须确保服务器时间准确（误差不超过 5 分钟）。

## 基础功能配置

### 进入配置页面

进入项目菜单 → **Webhook**

### 配置项说明

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 启用 Webhook | 开关，是否启用通知 | 是 |
| Webhook 地址 | 钉钉机器人 URL | 是 |
| 密钥令牌 | 加签密钥，机器人安全设置时填写 | 否 |
| 启用状态 | 选择触发通知的任务状态 | 是 |
| 通知模板 | 消息内容模板 | 是 |

### 启用状态选择

勾选需要通知的任务状态，如：
- ✅ 进行中
- ✅ 已解决
- ✅ 已关闭
- ❌ 新建（不通知）

### 保存配置

填写完成后，点击页面底部的 **保存** 按钮。

## 任务提醒配置

### 功能说明

每日定时提醒项目中没有指派任务的在岗成员，支持多项目和角色筛选。

### 配置步骤

1. **启用任务提醒**

进入 **项目 → Webhook**，在任务提醒区域勾选 **启用任务提醒**。

2. **设置提醒时间**

- **小时**：0-23，默认 9（上午 9 点）
- **分钟**：0-59，默认 0

3. **配置提醒角色**

选择需要提醒的角色，默认全选。只有被选中角色的成员才会收到提醒。

**说明**：系统自动排除内置角色（匿名用户、非成员用户）。

4. **编辑提醒模板**

支持 Markdown 和纯文本格式。

**可用变量**：
- `${project}` - 项目名称
- `${date}` - 提醒日期
- `${users}` - 成员列表，每行一个

**模板示例**：
```
【${project}】任务提醒（${date}）
以下成员当前没有被指派的未关闭任务：
${users}
```

5. **子项目控制（可选）**

勾选 **禁用子项目任务提醒** 后，所有子项目将无法启用任务提醒功能。

### 提醒规则

- **触发条件**：到达设定时间且是工作日
- **提醒对象**：
  - 具有选中角色
  - 在岗状态（工作状态为空或等于"在岗"值）
  - 没有指派的未关闭任务
- **项目范围**：当前项目 + 所有父项目 + 所有子项目
- **时间说明**：周末和法定节假日不提醒，调休上班日会提醒

### 多容器部署

插件使用数据库分布式锁，支持多容器并行部署，自动防止重复发送。

**配置要求**：
- 所有容器共享同一个数据库
- 无需额外配置，系统自动使用最佳锁策略

## 手机号强提醒配置

### 功能说明

在钉钉消息中 @ 用户，实现强提醒（弹窗 + 红色标记）。

### 配置步骤

1. **创建手机号自定义字段**

进入 **管理 → 自定义字段 → 新建**：
- **类型**：用户
- **名称**：手机号
- **格式**：文本
- 其他保持默认

2. **填写用户手机号**

进入 **管理 → 用户**：
- 点击用户编辑
- 在"手机号"字段填写手机号
- 保存

3. **在模板中使用变量**

在通知模板中包含 `${assigned_to}` 变量，系统会自动识别并 @ 指派人。

**注意**：仅在模板中包含 `${assigned_to}` 时才会触发 @ 功能。

### 提醒效果

| 用户是否有手机号 | 提醒方式 |
|-----------------|----------|
| ✅ 有手机号 | 强提醒（弹窗 + 红色标记） |
| ❌ 无手机号 | 普通 @ 提醒（显示 @昵称） |

### 多用户共享手机号

如果多个用户使用同一个手机号（如工作手机号）：
- 所有用户都会收到强提醒
- 消息中会显示所有被 @ 的用户昵称

## 子项目同步

### 功能说明

将当前项目的 Webhook 配置一键同步到所有子项目，节省重复配置时间。

### 同步步骤

1. **进入 Webhook 配置页面**

在父项目中选择 **Webhook** 菜单。

2. **配置当前项目**

先完成父项目的 Webhook 配置。

3. **找到子项目同步区域**

滚动到页面底部，找到"同步配置到子项目"区域。

4. **选择子项目**

- 点击"选择子项目"按钮
- 在弹出的列表中勾选需要同步的子项目
- 支持多选和全选

5. **保存并同步**

点击 **保存** 按钮，系统会自动同步配置。

### 同步结果

保存后会显示同步统计：
- **创建**：X 个新配置
- **更新**：Y 个现有配置

### 同步内容

完整的 Webhook 配置包括：
- 启用状态
- Webhook 地址
- 密钥令牌
- 启用状态列表
- 通知模板
- 任务提醒配置（启用、时间、模板、角色等）
- 禁用子项目任务提醒设置

### 注意事项

- 子项目必须已启用 Webhook 模块
- 同步会覆盖子项目原有配置
- 操作使用数据库事务，失败会自动回滚

## 模板编写指南

### 可用变量

#### 任务通知变量

| 变量 | 说明 | 示例 |
|------|------|------|
| `${user}` | 操作用户姓名 | 张三 |
| `${task}` | 任务标题 | 修复登录 bug |
| `${status}` | 任务状态 | 进行中 |
| `${project}` | 项目名称 | 网站开发 |
| `${url}` | 任务链接 | http://redmine.example.com/issues/123 |
| `${notes}` | 备注信息 | 已修复验证问题 |
| `${priority}` | 优先级 | 紧急 |
| `${tracker}` | 跟踪类型 | Bug |
| `${assigned_to}` | 指派人（触发 @ 提醒） | 李四 |

#### 任务提醒变量

| 变量 | 说明 | 示例 |
|------|------|------|
| `${project}` | 项目名称 | 网站开发 |
| `${date}` | 提醒日期 | 2026-03-12 |
| `${users}` | 成员列表（每行一个） | - 张三\n- 李四 |

### 模板格式

支持三种格式：

#### 1. 纯文本

```
${user} 更新了任务 "${task}"
状态：${status}
项目：${project}

查看详情：${url}
```

#### 2. Markdown

```markdown
## 📋 ${project} - 任务更新

**任务：** ${task}
**状态：** ${status}
**操作人：** ${user}
**指派人：** ${assigned_to}

[查看详情](${url})
```

#### 3. HTML

```html
<h3>${project} - 任务更新</h3>
<p><strong>任务：</strong>${task}</p>
<p><strong>状态：</strong>${status}</p>
<p><strong>操作人：</strong>${user}</p>
<p><a href="${url}">查看详情</a></p>
```

### 最佳实践

1. **保持简洁**：消息过长会被钉钉折叠显示
2. **关键信息优先**：标题、状态、链接最重要
3. **使用 Markdown**：格式更美观，支持链接点击
4. **@ 提醒**：在任务通知模板中包含 `${assigned_to}`
5. **统一风格**：保持项目间模板风格一致

### 任务提醒模板建议

```
【${project}】任务提醒（${date}）
以下成员当前没有被指派的未关闭任务：
${users}

请及时处理或更新任务状态。
```

## 常见问题

### 1. 插件安装后没有显示 Webhook 菜单

**原因**：项目未启用 Webhook 模块

**解决**：
1. 进入项目 → 设置 → 模块
2. 勾选 **Webhook** 模块
3. 保存

### 2. 消息发送失败

**检查清单**：
- Webhook URL 是否正确
- 机器人是否被移除或禁用
- 是否启用了加签但未填写密钥
- 密钥是否正确
- 服务器时间是否准确（加签要求）

**查看日志**：
```bash
tail -f log/production.log | grep Webhook
```

### 3. 任务提醒未发送

**检查清单**：
- 任务提醒功能是否已启用
- 是否到达设定的提醒时间
- 当前是否为工作日（周末不提醒）
- 是否有符合条件的成员（在岗、无任务、符合角色）

**查看日志**：
```bash
tail -f log/production.log | grep TaskReminder
```

### 4. @ 提醒不生效

**检查清单**：
- 模板中是否包含 `${assigned_to}` 变量
- 用户是否填写了手机号
- 自定义字段"手机号"是否正确创建

### 5. 子项目同步失败

**检查清单**：
- 子项目是否已启用 Webhook 模块
- 子项目 URL 是否正确配置
- 数据库是否有写入权限

### 6. 多容器部署重复发送

**原因**：容器未共享数据库或数据库锁表创建失败

**解决**：
1. 确认所有容器使用同一个数据库
2. 检查 `webhook_locks` 表是否存在
3. 查看日志是否有锁相关错误

### 7. 角色筛选不生效

**检查清单**：
- 是否选择了提醒角色
- 角色是否为内置角色（内置角色会被自动排除）
- 成员是否具有选中的角色

### 8. 时间时区问题

插件使用 Redmine 配置的时区，如需修改：

1. 进入 **管理 → 配置 → 显示**
2. 修改 **用户时区** 设置
3. 保存
