## 修复 AI 助手悬浮图标点击无法打开对话框
- 问题原因：Turbo/Turbolinks 页面切换后，widget 实例仍引用旧 DOM 元素，导致事件监听器绑定失效
- 修复 `assets/javascripts/ai_assistant/chat_widget_controller.js`：
  - 在 `init()` 中初始化 `this.eventListeners = []`
  - 重构 `bindEvents()`，统一通过 `addListener` 注册事件，便于后续解绑
  - 新增 `destroy()` 方法，页面切换前清理旧的事件监听器
  - 初始化逻辑改为：只要存在 `#ai-chat-widget`，就先销毁旧实例再创建新实例
  - 同时监听 `DOMContentLoaded`、`turbo:load`、`turbolinks:load`、`page:load`，兼容 Redmine 6/7
- 添加 `initScheduled` 防抖标记（microtask 级别），防止多个加载事件在同一次导航中重复触发初始化
- 修复 `assets/stylesheets/ai_assistant/chat_widget.css`：
  - `.ai-chat-toggle.ai-chat-active` 不再设置 `pointer-events: none` 和 `opacity: 0`
  - 改为 `opacity: 0.5` + `transform: scale(0.85)`，对话框打开后按钮仍可见且可点击关闭

## 修复重复声明错误 (messagesEl)
- 错误：`chat_widget_controller-9b49131e.js:170 Uncaught SyntaxError: Identifier 'messagesEl' has already been declared`
- 原因：浏览器缓存了旧版本 JS（旧版本中 bindEvents 有两次 `const messagesEl` 声明），当前源码已修复只有一处声明
- 修复：在 `initWidget` 中添加 `initScheduled` 防抖标记（Promise.resolve 级），防止多个加载事件在同一次导航重复触发初始化

## AI 插件三大功能增强

### 1. 系统名称动态化
- 所有硬编码 "Redmine" 改为 `Setting.app_title`（fallback "Redmine"）
- 涉及文件：`guard_prompt.rb`（GUARD_PREFIX_TEMPLATE 模板化）、`report_generator.rb`、`chat_controller.rb`
- locale 占位文本改为系统无关描述
- GuardPrompt 新增 `app_name`、`guard_prefix_for(name)` 方法

### 2. 版本关联显示版本名而非 ID
- `report_generator.rb`: 新增 `resolve_detail_value()` 方法，将 journal detail 中的 ID 值（fixed_version_id/status_id/priority_id 等）解析为实际名称
- `fetch_issues_assigned`、`fetch_issue_change_history` 中增加 `fixed_version` 字段（含 `:fixed_version` includes）
- `format_issues`、`format_change_history` 中展示版本名称

### 3. 报告生成包含状态/进度/预期完成时间
- `report_generator.rb` 新增 `fetch_status_summary()`（未关闭 issue 按状态分布统计）
- 新增 `fetch_overdue_issues()`（已过期未关闭的 issue 列表）
- `collect_data` 返回数据增加 `status_summary`、`overdue_issues` 字段
- `build_user_prompt` 增加「状态分布」+「逾期任务」两节
- `build_system_prompt` 增加按版本分组分析、进度分析、截止日期分析指引
- `chat_controller.rb` 的 `build_task_context` 增加 `done_ratio`、`due_date`、`fixed_version` 显示 + 逾期标记 ⚠️
- `TASK_QUERY_KEYWORDS` 增加 版本/截止/逾期/预计 等关键词触发数据注入

## 报告和聊天中的 issue 支持超链接跳转
- 前端 `renderMarkdown` 已支持 `[text](url)` Markdown 链接语法，无需修改
- `report_generator.rb`: 新增 `issue_url(issue_id)` 和 `issue_link(issue_id)` 方法，使用 `Setting.protocol` + `Setting.host_name` 构建完整 URL
- `format_issues`、`format_change_history`、`format_overdue_issues` 中的 `##{id}` 改为 `[##{id}](url)` Markdown 链接格式
- `chat_controller.rb`: 同样新增 `issue_url`/`issue_link` 方法，`build_task_context` 中 open_issues 和 today_updated 的 issue ID 均改为链接格式
- **AI 输出后处理兜底**：`ai_client.rb` 新增 `linkify_issue_ids(content)`，在 AI 返回内容后自动将独立的 `#ID` 文本转换为 `[#ID](url)`，已存在的 Markdown 链接不会被重复处理
- **Prompt 强化**：在 `report_generator.rb` 和 `chat_controller.rb` 的系统提示中明确要求 AI 保留 `[#ID](URL)` 链接格式
