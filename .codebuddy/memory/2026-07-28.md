## 修复 AI 聊天输入 #ID 仍返回自我介绍的问题
- 原因 1：`task_query?` 需要命中 2 个关键词，像 `#2175 任务总结` 只命中了「任务」，无法触发数据注入
- 原因 2：没有识别消息中的 `#ID` 特定任务编号，只查询当前用户的任务列表
- 修复 `chat_controller.rb`：
  - `TASK_QUERY_KEYWORDS` 增加「总结、概括、详情、详细」等中文词
  - `task_query?` 改为命中任意关键词 OR 包含 `#ID`
  - 新增 `extract_issue_ids(message)` 从消息提取 `#ID`
  - `build_task_context(message)` 支持两种模式：包含 `#ID` 时调用 `build_specific_issue_context`，否则调用 `build_user_assigned_context`
  - 新增 `build_specific_issue_context`：按 ID 查询任务并注入到上下文，包含作者、经办人、截止日期、进度、版本等信息
  - 调整 system prompt 结构：任务上下文放在最前面，并增加「当提供了任务数据时，必须基于数据回答，不要回退到通用问候语」的指令

## 未触发任务关键词时友好提醒
- 在 `chat_controller.rb` `build_system_content` 中增加 `else` 分支：当 `task_query?(message)` 返回 false 时，注入 `task_keywords_hint` 系统提示
- `task_keywords_hint` 返回引导性提示，告诉 AI 向用户友好地说明可用的关键词：
  - `#ID` 格式引用特定任务（如 `#123`）
  - 任务关键词：任务/task、我的任务/my tasks、待办/todo、指派/assigned
  - 报告关键词：报告/report、汇总/summary、总结/summarize、日报/周报/月报
  - 时间关键词：今天/today、本周/this week、本月/this month
  - 状态关键词：状态/status、优先级/priority、进度/progress、逾期/overdue、截止/due
- AI 会以友好语气引导用户使用这些关键词获取真实系统数据，而非简单回复「没有数据」

## 修复 AI 对话框 Markdown 链接渲染
- 问题：AI 返回的链接 `[#42](http://...)` 被拆成两行时，前端 `renderMarkdown` 无法识别，导致以纯文本形式显示
- 修复 `chat_widget_controller.js`：
  - 将行内格式（粗体、斜体、删除线、链接、图片）的处理提前到 `<br>` 转换之前，避免跨行 Markdown 语法被 `<br>` 打断
  - Markdown 链接正则改为 `/\[([^\]]+)\]\s*\(([^)\n]+)\)/g`，允许 `]` 与 `(` 之间存在空白/换行
  - 新增纯 URL 自动链接：提取已有的 `<a>` 标签作占位保护后，将剩余的 `http://` / `https://` URL 自动转为可点击链接

## 禁止 AI 建议指令式操作
- 问题：AI 在回复任务数据后主动提示用户可回复「进度改为100%」「状态改为已关闭」「添加备注：...」等指令，暗示 AI 能直接操作数据
- 修复：
  - `chat_controller.rb` 基础系统提示增加 READ-ONLY 声明：禁止生成任何暗示可修改/更新/删除/执行操作的提示；禁止主动让用户回复操作指令；用户要求修改数据时只能说明只读身份，不能给出分步操作指令
  - `lib/ai_assistant/guard_prompt.rb` 新增规则 **NEVER SUGGEST COMMAND-BASED OPERATIONS**：明确禁止 AI 说出截图中的命令式引导语，并强调 AI 没有执行命令的能力
  - 修复 `guard_prompt.rb` 中的 Ruby 格式字符串问题：中文示例里的 `100%` 被 `String#%` 解析为非法格式符，导致报告生成报 `malformed format string - %'`；将 `100%` 转义为 `100%%`，输出仍为 `100%`
